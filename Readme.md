```bison
input: expr { result = $1; };

expr:
    term
  | expr '+' term { $$ = $1 + $3; }

;

    factor

  | term '/' factor {
        if ($3 == 0) {
            yyerror("division by zero");
            YYABORT;

        $$ = $1 / $3;
    }
;

    NUMBER
  | '(' expr ')' { $$ = $2; }
;

```

## 为什么需要语法分析

前一章节我们提到，原始字符串处理起来太繁琐，所以需要词法分析把它切分成一个个单词（Token）。那为什么我们还需要语法分析呢？

我们对比下面两个字符串：

```text
"1, 2, 3"
"(1 + 2) * 3 + 4"
```

对于第一个字符串，它的结构是扁平的，只需要做简单的词法分析就可以把它提取为数组 `[1, 2, 3]`；但第二个字符串不同，它隐含着“先算括号里的，再算乘法，最后算加法”的层级结构与求值顺序。这种嵌套的层次语义仅靠扁平的 Token 列表无法表达，需要我们通过语法分析来获取。

## 从表达式到语法树

我们从 `(1+2)*3+4` 这个表达式开始理解语法分析。

人类在心算这个式子时是怎么拆解的呢？

1. 首先看整体：它是左边的 `(1+2)*3` 和右边的 `4` 相加；
2. 再看左半边：它是 `(1+2)` 和 `3` 相乘；
3. 最后看最里面：括号里是 `1` 和 `2` 相加。

如果我们把这种拆解过程画出来，会发现它天然是一棵树：叶子节点都是具体的数字或符号，而中间节点则代表一步步组合出来的子表达式：

```text
表达式: (1+2)*3+4
├── 子表达式: (1+2)*3
│   ├── 子表达式: (1+2)
│   │   ├── (
│   │   ├── 子表达式: 1+2
│   │   │   ├── 1
│   │   │   ├── +
│   │   │   └── 2
│   │   └── )
│   ├── *
│   └── 3
├── +
└── 4
```

仔细观察这棵树，你会发现一个奇妙的性质：运算优先级已经被编码进树的深度里了！ 越需要先算的部分，在树里藏得越深。只要沿着这棵树从叶子节点自底向上反向求值：先算最深的 `1+2=3`，往上一层算 `3*3=9`，最后在根节点算 `9+4=13`，就能自动以正确的优先级算出结果。

在编译器中，我们先用语法分析得到这样的层级关系。上图保留了括号等语法细节，称为语法分析树；去掉这些细节，只保留数字和运算等后续处理需要的结构，就得到了 AST（抽象语法树）。后面我们会亲手构建它。

## 如何让机器构建出这棵树？

人类靠数学直觉就能画出上面的树，但机器没有直觉，我们必须给它一套严格的规则。

### 第一步：最符合直觉的归纳规则

仔细观察算术表达式，无非是由数字、加号、乘号和括号不断组合而成的。我们可以用数学归纳法的思路写出 4 条最朴素的构造规则（用 `E` 代表表达式 Expression）：

```text
E -> 数字
E -> E + E
E -> E * E
E -> ( E )
```

其中 `A -> B` 读作“A 可以由 B 构成”或“A 可以展开为 B”。上面四句话翻译过来就是：表达式可以是一个单独的数字、两个表达式相加、两个表达式相乘，或者被括号包起来的一个表达式。

递归地套用这些规则，我们可以从最里面的数字开始，一步步把 `(1+2)*3+4` 归约成一个 `E`：

```text
1 + 2         => E + E => E   （先归约括号内部）
( 1 + 2 )     => ( E ) => E   （套上括号依然是 E）
( 1 + 2 ) * 3 => E * E => E   （与 3 相乘归约为 E）
(1 + 2)*3 + 4 => E + E => E   （最后与 4 相加归约为整体的 E）
```

把每一步归约倒过来展开，刚好就是我们前面画的那棵树！看起来问题似乎已经完美解决了？

### 第二步：遇到第一个矛盾——优先级冲突

别高兴得太早。现在请你只用上面那 4 条规则，试着去归约一个没有括号的式子：`1 + 2 * 3`。

方式一（先归约乘法，再归约加法）：

```text
1 + 2 * 3
=> E + E * E   （数字分别归约为 E）
=> E + E       （把右边的 2 * 3 按 E * E 归约为 E）
=> E           （把整体的 E + E 归约为 E）
```

这种方式建出来的树是 `1 + (2 * 3)`，求值结果为 7。

方式二（先归约加法，再归约乘法）：

```text
1 + 2 * 3
=> E + E * E   （数字分别归约为 E）
=> E * E       （先把左边的 1 + 2 按 E + E 归约为 E！）
=> E           （再把整体的 E * E 归约为 E）
```

这种方式建出来的树变成了 `(1 + 2) * 3`，求值结果为 9！

```text
    方式一的树 (结果=7)            方式二的树 (结果=9)
          +                             *
         / \                           / \
        1   *                         +   3
           / \                       / \
          2   3                     1   2
```

问题出在哪？ 同一个字符串，按照同一套规则，竟然合法地推导出了两棵完全不同的树！这种现象在编译原理中称为二义性。

根本原因在于：在 `E -> E + E` 和 `E -> E * E` 中，`+` 和 `*` 平起平坐。这导致乘法节点 `*` 的下面可以合法地长出一个加法节点 `+`（如方式二），违背了“先乘除后加减”的常识。

如何破局？——引入“分层”

要想彻底消灭方式二那棵错误的树，我们必须立下一条死规矩：乘法的子节点里，绝对不允许直接出现裸露的加法！

既然一个笼统的 `E` 无法区分“里面有没有加法”，我们就把表达式按优先级从低到高拆分成三个不同的层级（分别起名为 表达式、项、因子）：

1. 表达式（管加减，最外层）：由若干个“项”相加而成。
2. 项（管乘除，中间层）：由若干个“因子”相乘而成。因为它的组成部分只能是更底层的“因子”，裸露的加法根本混不进来！
3. 因子（最底层的基本单元）：它要么是一个纯数字；要么是一个带括号的表达式 `( 表达式 )`（一旦加上括号，内部就可以重新包含加法，相当于重置了优先级）。

同时，考虑到单独一个数字（比如 `42`）本身也是合法的表达式，每一层都必须留一条直接通往下一层的通道（例如“单独一个项也是表达式”）。
因此我们可以得到这样的递归规则：

```text
表达式 -> 表达式 + 表达式 | 项
项     -> 项 * 项 | 因子
因子   -> 数字 | ( 表达式 )
```

### 第三步：遇到第二个矛盾——结合性冲突

解决了不同运算符之间的优先级，我们再来看看相同优先级的运算符。假设我们引入减法，写出对称的规则：`表达式 -> 表达式 - 表达式 | 项`，然后去解析 `1 - 2 - 3`：

方式一（先归约左边）：

```text
1 - 2 - 3  =>  (1 - 2) - 3  =>  结果为 -4
```

方式二（先归约右边）：

```text
1 - 2 - 3  =>  1 - (2 - 3)  =>  结果为 2
```

诶？两个减号的优先级明明一模一样，为什么二义性又出现了！

问题出在哪？ 在 `表达式 - 表达式` 这个对称的结构里，减号的左边和右边都是 `表达式`，意味着两边都有资格继续往下分裂出新的减号。树既可以往左下角长，也可以往右下角长。

如何破局？——限制为单侧递归（左递归）

四则运算规定同级加减法必须从左往右算（左结合），在语法树上就表现为：左边的 `1 - 2` 必须藏在更深的左子树里先算出来，右边的减数绝不允许再直接包含同级的减法。

因此，我们只需要剥夺减号右侧继续分裂减号的权利，把右边强行降级锁死为 `项`：

```text
表达式 -> 表达式 - 项
```

这样一来，只有左边能继续展开成新的加减法，右边只能乖乖放乘除法或数字。`1 - 2 - 3` 就只能唯一地归约为 `(1 - 2) - 3` 了！（乘法 `项 -> 项 * 因子` 也是完全相同的道理）

---

### 第四步：水到渠成的上下文无关文法

现在，把“优先级分层”和“左递归保证左结合”这两套补丁合在一起（这里以 `+` 和 `*` 为例），我们就靠自己的逻辑一步步推导出了严密、无二义性的算术表达式规则：

```text
表达式 -> 项
表达式 -> 表达式 + 项
项     -> 因子
项     -> 项 * 因子
因子   -> 数字
因子   -> ( 表达式 )
```

这种用非终结符（如 `表达式`、`项`、`因子`）和终结符（如 `数字`、`+`、`*`）定义语言结构的规则体系，就叫做上下文无关文法（Context-Free Grammar, CFG）。

为了书写更紧凑，我们通常把左边相同的规则合并，用 `|` 表示“或”：

```text
表达式 -> 项 | 表达式 + 项
项     -> 因子 | 项 * 因子
因子   -> 数字 | ( 表达式 )
```

现在再回过头去看开头的 `(1+2)*3+4`，套用这套文法规则，机器就只能唯一地构建出下面这棵结构严谨的语法树了：

```text
表达式: (1+2)*3+4
├── 表达式: (1+2)*3
│   └── 项: (1+2)*3
│       ├── 项: (1+2)
│       │   └── 因子: (1+2)
│       │       ├── (
│       │       ├── 表达式: 1+2
│       │       │   ├── 表达式 -> 项 -> 因子 -> 数字 1
│       │       │   ├── +
│       │       │   └── 项 -> 因子 -> 数字 2
│       │       └── )
│       ├── *
│       └── 因子 -> 数字 3
├── +
└── 项 -> 因子 -> 数字 4
```

我们把减法和除法也加进来，文法变成：

```text
expr   → term | expr + term | expr - term
term   → factor | term * factor | term / factor
factor → NUMBER | ( expr )
```

在 Bison 中，`→` 写成 `:`，每组规则以 `;` 结束。由此我们可以写出:

```bison
input: expr;

expr:
    term
  | expr '+' term
  | expr '-' term
;

term:
    factor
  | term '*' factor
  | term '/' factor
;

factor:
    NUMBER
  | '(' expr ')'
;
```
类似flex，我们也可以在bison里指定某个规约发生时执行什么操作，其中我们可以使用
- $$ 表示规约父节点的值
- $i 表示第i叶子节点的值(符号也是一个叶子节点)
对于expr:term 这种单叶子的情形，bison会默认执行$$=$1。
由此我们可以写出:
```bison
input: expr { result = $1; };

expr:
    term
  | expr '+' term { $$ = $1 + $3; }
  | expr '-' term { $$ = $1 - $3; }
;

term:
    factor
  | term '*' factor { $$ = $1 * $3; }
  | term '/' factor {
        if ($3 == 0) {
            yyerror("division by zero");
            YYABORT;
        }
        $$ = $1 / $3;
    }
;

factor:
    NUMBER
  | '(' expr ')' { $$ = $2; }
;
```

### Flex
我们给出了这样的Token类型
```c
enum Token {
    Number(int),
    Operator(char),
    Punct(char),
    Unknown(char),
    Eof,
};
```
并使用和exp1类似的flex进行词法分析，见playground/arithmetic.l。
### Bison如何解析token

Bison 通过`yylex()->int` 这一接口获取Token.对于需要包含语义值的Token(例如数字)，通过yylval变量传值。
我们可以用`%token NUMBER`定义NUMBER这个编号，对于其他符号，这里简单返回它的ascii值。

因此对于数字，我们这样处理：

```c
    case Token::Number:
        yylval = token.payload.Number;
        return NUMBER;
```

其余分支将运算符和括号转换成ascii返回，将未知字符转换成 `YYUNDEF`，将输入结束转换成 `YYEOF`。

以 `(1+2)` 为例，传递过程如下：

| 输入     | `scanner_next()` 返回  | `yylex()` 返回 | 语义值 |
| -------- | ------------------------ | ---------------- | ---------------- |
| `(`    | `Token::Punct('(')`    | `'('`          | 不使用           |
| `1`    | `Token::Number(1)`     | `NUMBER`       | `1`            |
| `+`    | `Token::Operator('+')` | `'+'`          | 不使用           |
| `2`    | `Token::Number(2)`     | `NUMBER`       | `2`            |
| `)`    | `Token::Punct(')')`    | `')'`          | 不使用           |
| 输入结束 | `Token::Eof`           | `YYEOF`        | 不使用           |

### yyparse 如何使用这些符号

`main()` 调用 Bison 生成的 `yyparse()` 开始语法分析。`yyparse()` 在需要下一个输入符号时调用 `yylex()`。

`yyparse()` 内部维护分析栈，保存已经识别的符号、语义值和分析状态。根据文法生成的分析表，它决定接下来做什么：

- **移入**：把当前输入符号及其语义值放进栈。
- **归约**：把栈中符合某条规则的内容合成规则左侧的符号，并执行这条规则的语义动作，递归规约直到无法继续。

以加法规则为例：

```bison
expr '+' term { $$ = $1 + $3; }
```

当分析器决定按这条规则归约时，就把 `expr '+' term` 合成一个新的 `expr`，并执行花括号中的代码进行语义值的计算。

### AST 构建
我们来看`playgroud/ast.y`.首先是这段ShyC代码，它定义了一个二叉树
```c
struct Binary {
    char op;
    int left;
    int right;
};

enum Node {
    Number(int),
    Binary(Binary),
};

/* 节点统一存放，左右孩子和根节点都用数组下标表示。 */
Vec<Node> nodes = {0};
int root = 0;

fn binary(char op, int left, int right) -> int {
    Binary children = {op, left, right};
    nodes.push(Node::Binary(children));
    return nodes.len - 1;
}

/* 子树递归写入同一个 Writer，不生成中间字符串。 */
impl Display for Node {
    fn display(const self *node, WriterRef *out) -> int {
        switch (*node) {
        case Node::Number:
            return write!(out, "{}", node.payload.Number);
        case Node::Binary:
            return write!(out, "({} {} {})", node.payload.Binary.op,
                nodes.data[node.payload.Binary.left],
                nodes.data[node.payload.Binary.right]);
        }
    }
}
```
与常规二叉树不太一样的是，它使用数组模拟二叉树，数组索引模拟指针。
`Display` 决定节点的显示形式，入口用 `println!("{}", nodes.data[root])` 打印整棵树。`write!` 将左右子树继续写入同一个输出目标，递归过程中不需要为每棵子树创建字符串。

## exam

playground 是带着完成的例子。下面的练习需要你把同样的方法用到 ShyC 中，检查程序放在 `exam/`，编译器实现在 `compiler/`。

所有正常输入都使用完整的 ShyC 程序。先实现 `fn main()->int { return 42; }` 这个最小外壳，再向里增加表达式和语句，避免为了检查中间步骤给编译器增加额外模式。

### 1. run it：最小函数

识别无参数函数、`int` 返回类型、花括号和 return 语句。先让 `return 42;` 产生一棵树。

输出约定为：

```text
(program (fn main (block (return 42))))
```

函数体的 `block` 保存语句序列；程序的 `program` 保存函数序列。本节所有函数都返回 `int`，输出中省略这个固定类型。

### 2. 表达式

将 playground 的四则表达式接入 return，保留优先级、左结合和括号。表达式必须保留完整结构，不能在分析时提前算出结果。例如 `return 1 + 2 * 3;` 中的 return 节点应为 `(return (+ 1 (* 2 3)))`。

### 3. 变量声明与引用

支持 `int a = 表达式;`，并让表达式可以引用标识符。声明输出为 `(let a 表达式)`，引用直接输出变量名。一个函数体里可以有多条语句，输出时保持源代码顺序。

这一节不检查变量是否已经定义，也不建立符号表。我们只识别语法并保留结构。

### 4. println 调用

支持 `println!(字符串, 可选的表达式参数列表);`。这里的意思是字符串后可以没有参数，也可以用逗号跟上一个或多个表达式。

例如 `println!("hello");` 输出为 `(println "hello")`，`println!("{}", b);` 输出为 `(println "{}" b)`。字符串保留源代码中的引号和转义写法，不在本节解释转义或检查占位符数量。

### 5. 完整程序与多个函数

串起上面的规则，分析本节的完整示例。然后让程序支持一个或多个函数，并让函数体可以为空。空函数体输出为 `(block)`。

完整示例的输出应为一行：

```text
(program (fn main (block (let a 10) (let b (+ (* a 10) (- 20 (/ 30 3)))) (println "{}" b) (return a))))
```

### 6. 语法错误

处理缺分号、缺右括号、缺操作数等情况。遇到第一个错误就停止，不要求错误恢复。

语法错误写入 stderr，格式沿用 exp1：`<file>:<line>:<column>: error: syntax error`。位置指向引发错误的 Token 起点；如果缺少的内容直到输入结束才被发现，则指向 EOF 位置。行列从 1 开始，换行后列号恢复为 1，本节制表符按一个字符计数。可以了解 Bison 的 `%locations`，并在词法分析器中记录 Token 的起止位置。

有错误时退出码为 1，stdout 不输出 AST；成功时退出码为 0，stdout 只输出一行 AST。保留 exp1 的非法字符和未闭合块注释诊断。

### 检查方式

先构建自己的编译器，再运行检查：

```sh
make build
python3 exam/exam.py
```

也可以只检查某一层，例如：

```sh
python3 exam/exam.py expr
```

可选的层名为 `minimal`、`expr`、`variable`、`println`、`program`、`error`。检查程序只运行现有可执行文件，不自动构建。当前提供的编译器仍然是 exp1 的词法分析实现，需要完成上述练习后才能通过。

`make build` 和 `make shy_build` 继续保留；ShyISA 版本使用 `shyemu-user build/mycc.sfs <input>` 运行时，也应该输出相同的 AST。
